Pitch File 02 — Technical Architecture

Q1: Describe the end-to-end data flow from physical sensors to worker-facing alerts.
A:
- Ingests from 4 streams: geotechnical sensors, Sentinel-1 SAR backscatter, Copernicus DEM terrain, and Open-Meteo rainfall.
- FastAPI formats each reading through frozen Pydantic schemas and builds a 10-feature vector.
- The ML engine evaluates the reading and produces a RiskPrediction (Safe/Warning/Evacuation) with a risk score.
- Results stream over WebSocket (/ws/feed) in under 2.5 seconds to the Next.js 3D heatmap dashboard.

Q2: What is the FastAPI backend architecture and how is it structured?
A:
- Built with FastAPI on Python 3.12 with Uvicorn, structured into schemas, routers, and app lifecycle.
- Endpoints include POST /predict for on-demand inference and WebSocket /ws/feed for live telemetry streaming.
- Health checks (/health) enable cloud deployment monitoring and automated fail-fast startup checks.
- CORS is configured for Vercel production and local developer ports without route duplication.

Q3: Why Next.js 16 with App Router, React 19, and TypeScript 5.9 — and not other frameworks?
A:
- Next.js 16 App Router provides fast server components and Turbopack for instant sub-second hot reloading.
- React 19 automatic batching handles high-frequency WebSocket updates smoothly across maps and charts.
- TypeScript strictly enforces backend schema contracts to prevent UI crashes during live telemetry.
- Tailwind CSS enables responsive, modern dark-mode dashboards with zero build performance overhead.

Q4: How does the 3D pit visualization work with MapLibre GL?
A:
- MapLibre GL renders the Kusmunda mine pit as an interactive 3D terrain heatmap.
- Visualizes a 4x4 grid of 16 GeoJSON zones color-coded by real-time risk scores (0 to 1).
- 100% open-source and free, eliminating Mapbox API tokens and preventing vendor lock-in.
- 3D pitch and tilt controls give mine operators an intuitive spatial overview of pit walls.

Q5: How are the Pydantic data contracts designed and enforced?
A:
- Three frozen schemas define all contracts: SensorReading, RiskPrediction, and AlertEvent.
- The RiskLevel enum strictly locks values to "safe", "warning", or "evacuation".
- Risk scores are mathematically validated to stay between 0.0 and 1.0.
- Frontend TypeScript types hand-mirror backend schemas to ensure zero translation errors.

Q6: How does the mock-to-real model swap work with zero frontend changes?
A:
- Day 0 frozen Pydantic contracts guaranteed identical JSON payload shapes for mock and real models.
- Swapping from mock to real RandomForest required changing only the internal prediction logic.
- The WebSocket stream, frontend charts, and 3D map required zero code modifications.
- Proves clean API decoupling between data science pipelines and frontend presentation layers.

Q7: What is the ConnectionManager broadcast pattern and why is it used?
A:
- Manages active WebSocket client connections in memory for real-time telemetry streaming.
- Safely handles unexpected client disconnects without interrupting broadcast feeds to other users.
- An asyncio background task steps zone physics every 2.5s and broadcasts updates to clients.
- Graceful lifespan management cleans up tasks on server restarts without memory leaks.

Q8: What are the Turbopack and React 19 benefits for the dashboard?
A:
- Turbopack incrementally compiles only modified code, reducing dev build times to milliseconds.
- React 19 batches incoming sensor readings, predictions, and timestamps into single re-renders.
- Listener pattern in WebSocket hooks prevents memory leaks during page navigation.
- Delivers a smooth 60 FPS dashboard experience even during rapid telemetry updates.

Q9: How is the 4×4 zone grid designed and why 16 zones?
A:
- Divides the 4.8 km Kusmunda pit into a 4x4 regular grid of 16 GeoJSON zones.
- Generates 5,696 data points over 356 days, providing optimal training density for ML models.
- Balances fine spatial resolution with Sentinel-1 satellite 10-meter pixel coverage.
- Serves as the single geographic standard shared across satellite pipelines and the 3D UI.

Q10: How does the geospatial data pipeline work end-to-end?
A:
- Pulls 30-meter Copernicus GLO-30 DEM from Google Earth Engine and clips to the mine bounding box.
- Computes three terrain derivatives using richdem: slope degrees, downslope aspect, and profile curvature.
- Negative curvature flags concave rock faces prone to water retention and rock detachment.
- Zone-averages terrain values into static features that feed the 10-feature ML model vector.

Q11: How is Sentinel-1 SAR backscatter processed?
A:
- Queries Sentinel-1 dual VV/VH radar from Google Earth Engine over a 12-month window.
- Locks to descending orbit tracks to maintain constant radar incidence angles and prevent drift.
- Extracts zonal mean VV (surface roughness/moisture) and VH (structural volume scattering) in decibels.
- Provides satellite proxy signals for rock mass disturbance and ground moisture before failures.

Q12: How is Open-Meteo rainfall integrated and why is no API key needed?
A:
- Queries Open-Meteo historical archive API using mine GPS coordinates without requiring paid API keys.
- Fetches 356 days of daily precipitation data derived from open ERA5-Land reanalysis.
- A single pit-center query covers the entire 4.2 km mine, avoiding redundant network calls.
- Validated with zero missing or negative values, directly feeding our pore pressure models.

Q13: Why MapLibre GL instead of Mapbox GL?
A:
- Mapbox requires credit cards, paid access tokens, and caps free loads at 50,000 per month.
- MapLibre GL is completely open-source (BSD-3), zero-cost, and runs without API keys.
- Delivers identical 3D terrain rendering and vector tile capabilities with zero vendor lock-in.
- Matches our core mission of making mine safety technology affordable for all Indian mines.

Q14: How is the schema contract enforced between frontend and backend?
A:
- Pydantic models validate incoming payloads on the backend, rejecting bad data with 422 errors.
- TypeScript interfaces enforce strict type-checking on the frontend during compilation.
- Displacement thresholds (50 and 120 mm/day) are locked as matching constants in both codebases.
- Eliminates runtime field mismatches between Python backend services and React components.

Q15: Why WebSocket over polling for real-time telemetry?
A:
- WebSocket establishes a persistent connection that pushes data instantly when new readings arrive.
- Eliminates HTTP polling overhead, saving 100-300 ms of latency and 99% of network bandwidth.
- Upgrades via standard HTTP 101 handshake, transmitting lightweight telemetry frames in real time.
- Features automatic 3-second reconnection logic so dashboards recover instantly after network drops.
